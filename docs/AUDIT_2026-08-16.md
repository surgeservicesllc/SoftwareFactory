### Notes on what was checked and found sound

- **No hard-broken internal link, missing API route, or 404ing image exists.** Every `href`/`router.push`/`redirect()` target resolves to a real page or a `next.config.ts` 308; every `fetch("/api/…")` in `components/` maps to an existing handler; the app ships no `<img>` elements at all (icons are inline SVG), so there is nothing to 404. The runtime sweep confirmed: zero failed subresource requests other than the expected 503s from the intentionally-unconfigured Supabase environment and the deliberate 404 probe.
- The `useTenantList` consoles (Runs, Backlog, Reports, Agents, Commands) have correct loading/signed-out/setup/error/empty states; detail views render "No … evidence has been recorded" rather than fabricating data; `NotConnectedBadge` wording matches the AGENTS.md contract where used; manifest icons all exist at correct sizes; sitemap/robots list only real routes; portal token contrast passes AA for all text pairs; a global `:focus-visible` outline exists; `prefers-reduced-motion` is honored.

## Methodology

**Executed (runtime):** `npm ci` and a production build (`next build`, exit 0, all routes emitted) on the repo at `main` (`d266b17`), served with `next start` on localhost with **no Supabase environment configured** — the documented signed-out/unconfigured presentation, which is what the repo's own e2e suite exercises. A Playwright (Chromium) sweep visited all 29 routes — 6 marketing pages, 19 `/solutions` pages (including `/solutions/admin` and a dead-UUID `/solutions/portfolio/[projectId]`), `/offline`, `/auth/sign-in`, `/auth/sign-up`, and a deliberate 404 probe — at **375×812 (mobile), 768×1024 (tablet), and 1440×900 (desktop)**: 87 page visits plus targeted re-visits. Collected per visit: HTTP status, console errors, every failed subresource request, landmark/heading/label inventory, internal link inventory, horizontal-overflow detection, layout-shift (CLS) observation, and axe-core scans (at mobile and desktop). Four routes were re-swept with a DOM-loaded wait after a first-pass network-idle timeout that turned out to be a sweep artifact of route prefetching, not a product defect (verified by request-count probing). The pricing-table overflow (#14) and the duplicate-banner/landmark/heading-order findings (#15–#18) were found at runtime and then traced to source.

**Source-inspected:** every page and component under `app/(marketing)/`, `app/(portal)/`, `components/`, `lib/marketing/`, plus `app/layout.tsx`, `app/globals.css`, `next.config.ts`, `proxy.ts`, `public/` (including `sw.js`), `app/manifest.ts`, `app/sitemap.ts`, `app/robots.ts`, and the API route handlers referenced by the audited components. The full route tree and redirect table were enumerated and every internal href and fetch target checked against them. Contrast ratios were computed from the actual color token values (the app ships a single dark theme; there is no second theme to audit — `app/layout.tsx` pins `colorScheme: "dark"`). Status-truthfulness findings (#6–#8, #24–#29, #51) are source-inspected: they concern what the code measures versus what the UI asserts, which a signed-out runtime sweep cannot fully exercise; each is marked with its exact source reference. One caveat on the runtime environment: with no Supabase env the APIs return 503 where production returns 401 for signed-out visitors — findings #10 and #30 were traced through both codes in source, and #10's error path triggers on any non-OK response including production's 401.

**Not audited:** authenticated (signed-in) states, hosted-database-backed rendering, and live provider integrations — all require credentials that this audit environment intentionally does not hold.

This audit deliberately makes **no code change**; every suggested fix is a proposal for the owner.
